# SEO and AEO setup

This document explains why `novita-myanmar.com.mm` was not showing page content in search results and what changed to fix it.

## Root cause

The site is a Laravel + Inertia + React application. Before this change it was **client-side rendered only**:

- The initial HTML contained an empty `<div id="app"></div>` and only a `<title>Novita</title>`.
- Page titles, meta descriptions, Open Graph tags, canonical URLs, JSON-LD, and the visible page content were created by JavaScript after the page loaded.
- Google can render JavaScript, but it is slower and less reliable. Bing, social preview crawlers, and most AI answer-engine crawlers do not render JavaScript at all. They saw an empty page.
- Inertia SSR was enabled in `config/inertia.php`, but there was no `resources/js/ssr.tsx` entry and no SSR build output, so SSR never ran.

## What changed

### 1. Server-side rendering (SSR)

- Added `resources/js/ssr.tsx`.
- Added the SSR entry to `vite.config.ts`.
- `npm run build` now builds both the client bundle and `bootstrap/ssr/ssr.js`.
- The initial HTML now contains the page content, `<title>`, description, canonical URL, Open Graph/Twitter tags, and JSON-LD.

### 2. Metadata and structured data

- `SeoHead` now always emits a canonical URL and a robots meta tag.
- Canonical URLs use `https://novita-myanmar.com.mm` and strip filter/search query strings.
- Open Graph URLs and images are absolute; a 1200×630 `public/og-default.png` was added.
- Removed the invalid `SearchAction` (there is no `/search` route).
- Removed placeholder social profile URLs from Organization schema. Real social URLs set in admin settings are added automatically.
- Removed the price-less `Offer` from Product schema.
- Added `NewsArticle` schema for news articles and `JobPosting` schema for job pages.
- Added FAQ schema on the contact page (already present) and `ItemList` schema on the news index.
- Added a generic fallback `<title>`, description, and Open Graph tags in `app.blade.php` for when the SSR server is temporarily unavailable.

### 3. Crawler files

- Updated `public/robots.txt` with `Sitemap: https://novita-myanmar.com.mm/sitemap.xml`, admin/login disallows, and a note that AI crawlers are welcome.
- Added `public/llms.txt` with company facts, key pages, FAQs, and a preferred citation format for AI answer engines.
- Updated `routes/seo.php`:
  - Deduplicated sitemap URLs.
  - Added `lastmod` dates.
  - Added active, non-expired job pages.
  - Removed noindexed legal pages from the sitemap.
  - Kept sitemap and robots routes consistent with the static files.

### 4. News pages

- Public news now uses the database (`NewsController`) instead of the old hardcoded arrays.
- Unknown news slugs return HTTP 404 instead of silently showing the first article (soft-404/duplicate content).
- The 11 legacy hardcoded news slugs now 301 redirect to `/news` instead of returning 404.
- News images use a public URL accessor and fall back to a default image when the file is missing.
- News article metadata and `NewsArticle` schema now come from the database.

## Deployment requirements

SSR needs a Node.js process running on the server. Laravel calls it over HTTP at `127.0.0.1:13714`.

### Build

Run this on the server after deploying the code:

```bash
composer install --no-dev --optimize-autoloader
npm ci
npm run build
php artisan config:cache
php artisan view:cache
```

`bootstrap/ssr/` is gitignored, so it must be generated by `npm run build` on the server. Do not use `npm ci --omit=dev` for the build: Vite and the React compiler are needed to compile the assets. You can prune dev dependencies after the build if your deployment process requires it.

> **Do not run `php artisan route:cache` while the app uses closure routes.** The current `routes/web.php` and `routes/seo.php` contain closures, so route caching will fail. If a stale route cache exists, run `php artisan route:clear`.

### Start the SSR process

Use Supervisor or systemd. Example systemd unit (`/etc/systemd/system/novita-ssr.service`):

```ini
[Unit]
Description=NOVITA Inertia SSR server
After=network.target

[Service]
Type=simple
User=www-data
Group=www-data
WorkingDirectory=/var/www/novita
ExecStart=/usr/bin/php /var/www/novita/artisan inertia:start-ssr
Restart=always
RestartSec=5
StandardOutput=append:/var/log/novita-ssr.log
StandardError=append:/var/log/novita-ssr-error.log

[Install]
WantedBy=multi-user.target
```

Enable and start it:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now novita-ssr
```

If you use Supervisor instead:

```ini
[program:novita-ssr]
command=php /var/www/novita/artisan inertia:start-ssr
directory=/var/www/novita
autostart=true
autorestart=true
user=www-data
redirect_stderr=true
stdout_logfile=/var/log/novita-ssr.log
```

Restart the SSR process after every deployment that changes frontend code:

```bash
sudo systemctl restart novita-ssr
# or: sudo supervisorctl restart novita-ssr
```

If `node` is not on the service `PATH` (for example, when using nvm), pass the absolute path:

```bash
php artisan inertia:start-ssr --runtime=/absolute/path/to/node
```

### Environment

Make sure production `.env` contains:

```dotenv
APP_ENV=production
APP_DEBUG=false
APP_URL=https://novita-myanmar.com.mm
VITE_APP_URL=https://novita-myanmar.com.mm
```

`VITE_APP_URL` is compiled into the frontend at build time and is used for canonical and social URLs. If it is omitted, the code falls back to `https://novita-myanmar.com.mm`, but setting it explicitly avoids surprises.

Then clear and rebuild caches:

```bash
php artisan optimize:clear
php artisan config:cache
```

## Verification

1. Check the SSR process:

```bash
php artisan inertia:check-ssr
```

Expected: `Inertia SSR server is running.`

2. Check the initial HTML (not the browser-rendered DOM):

```bash
curl -sL https://novita-myanmar.com.mm/ | grep -E '<title>|description|canonical|og:title'
```

The response should contain a real title, description, canonical URL, and page content.

3. Check crawler files:

```bash
curl -sL https://novita-myanmar.com.mm/robots.txt
curl -sL https://novita-myanmar.com.mm/sitemap.xml
curl -sL https://novita-myanmar.com.mm/llms.txt
curl -sI https://novita-myanmar.com.mm/og-default.png
```

4. If SSR is down, the site still works via client-side rendering (Inertia falls back), but crawlers will see the fallback metadata and an empty app shell. Keep the SSR process supervised.

## Known data issues to fix in the admin panel

- **Job deadlines are in the past.** All four active job listings have deadlines before 25 October 2026. They are excluded from the sitemap, marked `noindex`, and omitted from `JobPosting` schema until the deadlines are updated. The job pages still work and show an "application deadline has passed" notice.
- **News images are missing from storage.** The database points to `news/*.jpg`, but those files are not present. News pages use a temporary fallback image, and social previews use `og-default.png`. Upload the real images to the public disk to restore article-specific images.
- **Social profile URLs are placeholders.** The settings contain `facebook.com/novita`, `linkedin.com/company/novita`, and `youtube.com/novita`. These are filtered out of `sameAs` until real profile URLs are entered in the admin settings.
- **Some seeded news and job copy is template text.** For example, the "NOVITA Launches New Product Line" article mentions industrial valves, pumps, and control systems, and the Sales Executive job mentions industrial clients. Replace this copy with real pharmaceutical content before requesting indexing.
- **Only four news articles exist in the database.** The previous page had 11 hardcoded placeholder articles. The live `/news` page now shows the four published database articles; add real news through the admin panel.

## Search engine follow-up

Code changes alone do not force a recrawl. After deployment:

1. Google Search Console:
   - Verify the `https://novita-myanmar.com.mm` property (or the domain property).
   - Submit `https://novita-myanmar.com.mm/sitemap.xml`.
   - Use URL Inspection on the home page and key pages, then click **Request Indexing**.
2. Bing Webmaster Tools:
   - Add the site and submit the sitemap.
3. Check for manual actions and security issues in Search Console.
4. Give Google 1–4 weeks to recrawl. Use the URL Inspection "Live test" to confirm the rendered HTML contains content.

## AEO notes

AEO (Answer Engine Optimization) depends on the same server-rendered content plus clear entity and citation signals:

- `llms.txt` gives AI crawlers a concise company summary, key URLs, FAQs, and a preferred citation.
- Organization, WebSite, BreadcrumbList, NewsArticle, JobPosting, Product, and FAQPage JSON-LD describe the entity and its content.
- `robots.txt` allows AI crawlers; it does not block them.
- Keep company facts, addresses, phone numbers, and page content consistent across the site.
- Publish real, dated news and product/regulatory updates so answer engines have fresh, citable material.
